# Method — building a full brand identity system with an AI agent

This is the workflow behind a real client engagement: a two-character Chinese tech brand went from
"the client picked a logo draft" to a 39-page brand manual, print-ready business cards, Office templates,
web assets and merch — in a few working sessions, every file generated by scripts and verified by machine.

The method is opinionated. Every rule below exists because skipping it cost a round of rework.

---

## The acceptance line

**A version of visual work is accepted only when it could be published on Behance as a portfolio piece.**
Complete and usable is not enough: tell a story, lay out every board by hand, show believable mockups,
proof both languages, use real data. After each version, run the blind review in `REVIEW.md`; if the score
is below the pass line, optimize and review again.

## Phase 0 · Three checks before you draw anything (10 minutes)

1. **What does the client already use?** `curl` their website: logo, CSS colors, fonts.
   In the source project the live site used a *completely different* older brand. Building a manual
   that the website ignores splits the brand in two — surface it on day one.
2. **Do the URLs and emails that will be printed actually work?**
   `dig +short www.<domain>` and `dig MX <domain>`. The source project's `www` had no DNS record;
   it almost got printed on 1,000 business cards.
3. **Can the logo's font be used commercially?** System fonts (PingFang, Microsoft YaHei, Helvetica
   bundled with an OS) are licensed for display on that OS — **not** for logos. Open fonts under
   SIL OFL (Source Han Sans / 思源黑体, Source Sans 3, Smiley Sans, LXGW WenKai) are safe.

Also collect up front: legal company name, every person's card data, the slogan, and anything the
client already wrote about the name's meaning.

## Phase 1 · Wordmark: rebuild a chosen draft on a licensable font

Clients often fall in love with a draft set in a font they can't use. Don't redraw by eye — **match by numbers**:

1. Take the approved draft's outlines (SVG). Split them per character by x-position.
2. Load an OFL **variable** font (e.g. Source Han Sans VF). For each character, scale its glyph to the
   draft's character height and center it on the draft's character center.
3. **Binary-search the weight axis** until the ink area (rasterized, non-zero fill) matches the draft
   within ~2%. Use one weight for all characters.
4. Merge overlapping contours (`skia-pathops`) — variable fonts keep overlaps; designers editing nodes
   in Illustrator will hate them.
5. Overlay draft vs rebuild and show the client: same size, same weight, *the font's own strokes*.

You borrow **metrics only, never outlines**. That is what makes the result legally clean.
`scripts/glyph_match.py` implements steps 2–4.

### Make it ownable

A rebuild on an open font is generic (anyone can type it). Add **one signature detail derived from the
icon** — in the source project the icon's doors had a 16° top edge, so the dot of one character and the
top of a vertical stroke got the same 16° cut. Measure the parameter from the icon geometry; don't invent it.
Offer 2 variants (subtle / stronger); let the client choose.

## Phase 2 · Find the signature parameter and reuse it everywhere

Pick one measurable property of the icon (an angle, a ratio, a corner radius) and make it the system's DNA:
wordmark detail, card panel edges, slanted section dividers, icon tops, badge shapes, the animation.
**Use it only where it reads naturally.** A 16° slant across a 1440 px web section drops 400+ px —
apply it to a 360 px corner instead. A monitor icon with a slanted top stops looking like a monitor.

## Phase 3 · Lockups × color modes as a matrix, generated

Lay out every combination from one master SVG, programmatically:

- Layouts: horizontal, vertical, icon, wordmark, + slogan versions, + bilingual (CN/EN), + long-name version.
- Modes: full color, reverse (dark bg, keep brand-color icon), mono black, mono white.
- **Mono versions knock out** inner shapes with even-odd fill (transparent, not white) so the background
  shows through — that is what stamps, foil and photos need.
- Artboards tight to artwork; clear space is a rule in the guide (e.g. X = ¼ icon height), not padding in the file.
- Bilingual: justify the English line to the Chinese width only when the tracking stays reasonable;
  for a 4-character name it explodes into "C L O U D …" — left-align with fixed tracking instead.
  Size the English by the font's **cap height**, not ink bounds (descenders like Q skew it).

Export with Illustrator scripting (`scripts/ai_export.jsx`): AI (CC-compatible), PDF, and a separate
CMYK set with **brand-specified CMYK values** (not automatic ICC conversion). EPS as AI8-compatible —
AI10+ EPS embeds private editing data (~0.8 MB each).

## Phase 4 · Color: respect the client's color, fix contrast with usage rules

If the client specifies a brand color, never change it. Measure WCAG contrast (`scripts/brandcolor.py`):
a bright blue on white is typically ~3.9:1 — fine for large text, not for body text. Fix with **usage**:
white-on-brand only for bold ≥ 18.7 px (14 pt); small text and links in the ink color, brand color as
underline/icon/fill. Tint ramps in OKLCH (perceptually even). Print CMYK for tints: convert via ICC and
compare candidates on screen — naive "10% of the brand CMYK" came out lavender; converting the screen tint through ICC gave a clean light blue.

## Phase 5 · Auxiliary graphics derived from the icon

Following a mature brand manual's structure (symbol crop, all-over pattern, badges, line icons/illustration),
translate each layer to the brand's own shapes:

- **Sequence** — the icon element in N frames (e.g. a door opening); doubles as hero visual and animation.
- **Pattern** — the element tiled, half-drop offset. Keep its real proportions: shrink a door too much and
  it reads as a ▶ play button.
- **Hatch** at the signature angle, **badge** with ring text, **line icon set** on one grid/stroke.
- Animation: often free from the geometry — scaling a door's width while keeping its vertical drop
  makes the slope steepen = perspective of opening. Pure CSS, honors `prefers-reduced-motion`.

## Phase 6 · Print: business cards and other press files

- Let the client choose among ~5 directions shown with their real data; then produce all people.
- Outline all text (fontTools pen → SVG paths). Build art with **extra bleed** (4 mm), then in Illustrator
  shrink the artboard to trim and save **PDF/X-1a** with bleed. Illustrator rounds bleed offsets to whole
  points — 8.5 pt becomes 8 pt (2.82 mm). Use 9 pt (3.18 mm) and paint 4 mm of art.
- Small text in single black (K100 / K65), never 4-color — misregistration blurs it.
- Verify by parsing the PDF: TrimBox/BleedBox size, only expected CMYK operators, zero fonts
  (`scripts/print_check.py`). Measure safe-zone compliance by rasterizing and finding the lowest dark pixel.

## Phase 7 · Digital and web assets (design only)

favicon set (small sizes from a simplified mark), 1200×630 share card, WeChat covers 900×383 + 200×200,
email signatures as HTML tables, social avatars (1:1, shapes inside a 70% safe circle; never a square
inside the circle), `tokens.css` with CSS variables and `.brand-*` component classes, an SVG icon sprite,
product sub-brand badges in the parent's language, spot illustrations made only of brand shapes.

## Phase 8 · Office templates people actually use

- PPT: `python-pptx`, 8 layouts (cover, TOC, section, content, 3-column, data, quote, closing), all text
  editable. Preview by exporting through Keynote.
- Letterhead as a **Word template** (`python-docx`), not just a PDF. No bleed colors — office printers
  can't print to the edge.
- Ship the OFL font files with the templates (redistribution is allowed) plus a one-line install note.

## Phase 9 · Assemble the manual

Each page is an HTML file rendered twice: PNG for review and a vector PDF (`@page` sized to the page).
Sections: A concept (name meaning, positioning vs slogan, logo meaning, wording rules) · B basics
(logo, construction grid in X units, clear space & minimum size, lockups, color modes, bilingual,
misuse, typography, color, auxiliary graphics) · C applications. A compile script regenerates every
page, computes TOC page numbers, and merges. Text on pages stays short — one headline, one or two lines.

## Phase 10 · Deliver

One folder per use (manual, logo RGB/CMYK, print files, templates, fonts, avatars, digital, web, merch)
with a "read me first". Email limits: keep each message's attachments ≤ ~18 MB raw (base64 adds ~37%);
`scripts/split_for_email.py` packs folders into numbered zips and verifies nothing is missing.

## Across all phases · Generate references with an image model, redraw in Illustrator

Use an image model (Gemini via `scripts/gemini_image.py`) at every design stage: copy tone, pattern
directions, compositions, real-scene mockups. Treat its output as a **reference only**. The deliverable is
always redrawn as vectors in Illustrator, with colors snapped to the spec; never ship the raw AI image, and
don't let automatic tracing be the final artwork.

- For **portfolio and final mockups**, have it generate **blank scenes only** and composite your vector artwork
  onto them yourself (see PITFALLS). Feeding it your artwork as a reference looks convincing but redraws
  letterforms; use that only for exploring directions.
- Send only your own design output or public material. Never client contact data, secrets or whole project folders.
- The model redraws, it does not paste. Neither small text nor wordmark letterforms are safe. State "do not change any
  text, keep Simplified Chinese" in the prompt and **proof every word** of the result (a card address came back
  converted to Traditional Chinese).

## The verification habit

Never trust "it looks done". After every generation step: render it and **look**, or measure it.
Most bugs in the source project were caught only this way — a missing path in an overlay, a font
fallback to Times, a slogan running off a roll-up banner, a CMYK tint that turned purple.
See `PITFALLS.md` for the full list.
